## 本轮已处理的四项问题

1. Session `JsonValue`：Bridge 保留本地递归类型根，并与官方
   `@deepseek-ai/dsh-session` `JsonValue` 做双向可赋值断言。官方 Session
   类型变化会在构建阶段显式失败，不再依靠直接 re-export 穿过 Typert 的
   外部递归类型边界。
2. Typert generator/protocol 版本错位：构建器先解析 DSH，再根据同一
   release family 解析 generator、protocol、Session 和客户端支持包；不再
   混用各包滞后的 npm `latest` 标签。Host/Remote 输出要求 protocol-native，
   不满足时 fail closed。
3. DSH 自生成状态：已记录 DSH `0.1.1-rc.1` 对
   `profiles/<profile>/cordis.yml` 的重写契约。Harman 只拥有
   `cordis.patch.yml` 输入、materialized view、lock 和 managed marker；
   DSH 派生 root 和 cache 不进入权威 lock。相应本机回归、latest 直跑和
   community bundle 组合证据已归档。
4. 升级/卸载/社区插件/非 Harman 路径：本机及 `codex-test` 均通过 66/66
   Core 回归；新增升级后社区 bundle 仍进入 materialized view、用户 prefix
   重装/卸载、状态保留和非 Harman prefix 文件保留；stock DSH latest 直跑
   也不依赖 Harman Bridge。

`@deepseek-ai/dsh-type-meta` 当前仍未在 npm 发布，但 pre-2 不再生成其临时
构建期 facade，也不在输出声明中使用 `GatewayService`/`TypeRTRemote`。当前
生成链使用已发布的 protocol-native contract；未来若上游引入正式兼容包，须
通过 release-family 构建和兼容合同后再替换静态分析 adapter。
